Design Notes

Control Plane

  • The hub runs in one management cluster.
  • The hub never connects to target Kubernetes APIs.
  • Site agents connect outbound to the hub over WireGuard and mTLS gRPC.
  • Plans are signed and cached locally by site and instance.

Failure Model

  • Patroni and etcd own PostgreSQL leadership.
  • Hub loss pauses globally coordinated changes.
  • Disconnected agents may repair safe cached drift only.
  • LoadBalancer address changes, membership changes, rollouts, restore, deletion, and upgrades require hub connectivity.

Namespace Ownership

Agents enforce namespace ownership with labels. Existing unlabeled namespaces are not adopted.

multisite-postgres.dev/enabled: "true"
multisite-postgres.dev/hub-domain: hub.example.com
multisite-postgres.dev/site-registration-uid: <site-uid>
multisite-postgres.dev/instance-uid: <instance-uid>

Security Boundaries

  • Hub can issue desired changes but cannot read workload Secret values.
  • Agent has broad rights for managed resource types in its cluster.
  • Trust anchors are separate for registration, plan signing, hub-agent mTLS, WireGuard, workload TLS, Vault, and pgBackRest.
  • Kubernetes Secret encryption at rest is required.

Production Caveats

  • Qualify StorageClasses, snapshot/clone behavior, and PostgreSQL upgrade duration before production.
  • Validate WireGuard UDP LoadBalancer failover and ExternalDNS behavior on the target platform.
  • Validate Vault policies and cert-manager issuer chains per site.
  • Run restore and major-upgrade drills against representative data sizes.
