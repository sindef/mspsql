Install

Use plain Kubernetes manifests rendered by Kustomize. Install the hub once. Install site agents by applying the hub-generated registration bundle to each target cluster.

Prerequisites

  • One management cluster for the hub.
  • One or more target Kubernetes clusters for PostgreSQL sites.
  • kubectl context for every cluster.
  • cert-manager on hub and site clusters.
  • LoadBalancer support for hub gateway UDP/TCP Services.
  • Vault reachable from each site, with Kubernetes auth configured.
  • S3-compatible object storage for pgBackRest.
  • Approved StorageClasses and, for major upgrades, snapshot or PVC clone rollback support.

Set Contexts

export HUB_CTX=hub
export VIC_CTX=vic
export NSW_CTX=nsw
export QLD_CTX=qld
export VERSION=__MSPSQL_VERSION__

Render Manifests

Clone the matching tag and pin released images before applying manifests.

git clone https://github.com/sindef/mspsql.git
cd mspsql
git checkout "v${VERSION}"

mkdir -p rendered

cp -R config /tmp/mspsql-config
(cd /tmp/mspsql-config/default && kustomize edit set image controller=ghcr.io/sindef/mspsql:${VERSION})
(cd /tmp/mspsql-config/tun-device-plugin && kustomize edit set image tun-device-plugin=ghcr.io/sindef/mspsql-tun-device-plugin:${VERSION})

kustomize build /tmp/mspsql-config/crd > rendered/00-crds.yaml
kustomize build /tmp/mspsql-config/default > rendered/10-hub.yaml
kustomize build /tmp/mspsql-config/tun-device-plugin > rendered/20-tun-device-plugin.yaml

Release images are published by immutable version tag, signed by digest, and built with SBOM and provenance attestations. Pin hub, TUN plugin, generated site-agent, gateway, WireGuard, PostgreSQL runtime, and upgrade images by digest before production apply.

Upgrade Order

HubSite agentSupported behavior
NNAll operations permitted when registrations advertise the operation capabilities required by the signed plan.
NN-1Safe reconciliation can continue. Major upgrades are blocked with AgentCapabilityMissing until every target site advertises major-upgrade-sync-before-writes.
N-1NAgents accept signed v1alpha1 plans and ignore unknown optional fields. New required operations must wait until the hub is upgraded.

Rollback is supported within a single v1alpha1 storage window. Do not downgrade after applying a CRD storage-version migration or a required-capability operation that the older hub cannot produce or repair.

Install Hub

kubectl --context "${HUB_CTX}" apply -f rendered/00-crds.yaml
kubectl --context "${HUB_CTX}" apply -f rendered/20-tun-device-plugin.yaml
kubectl --context "${HUB_CTX}" apply -f rendered/10-hub.yaml

kubectl --context "${HUB_CTX}" -n mspsql-system rollout status deploy/mspsql-controller-manager
kubectl --context "${HUB_CTX}" get crd | grep multisite-postgres.dev

Create Site Registrations

Create one SiteRegistration on the hub for each target cluster. The spec is site policy: allowed StorageClasses, issuers, rollback methods, and address pools.

kubectl --context "${HUB_CTX}" apply -f docs/examples/site-registration.yaml
kubectl --context "${HUB_CTX}" get siteregistration
kubectl --context "${HUB_CTX}" wait site/production-vic --for=jsonpath='{.status.phase}'=PendingRegistration --timeout=5m
kubectl --context "${HUB_CTX}" wait site/production-nsw --for=jsonpath='{.status.phase}'=PendingRegistration --timeout=5m
kubectl --context "${HUB_CTX}" wait site/production-qld --for=jsonpath='{.status.phase}'=PendingRegistration --timeout=5m

Install Each Site

Fetch the generated registration URL from the hub and apply it to the matching target cluster.

VIC_URL="$(kubectl --context "${HUB_CTX}" get site production-vic -o jsonpath='{.status.registrationURL}')"
kubectl --context "${VIC_CTX}" apply -f rendered/20-tun-device-plugin.yaml
kubectl --context "${VIC_CTX}" apply -f "${VIC_URL}"

NSW_URL="$(kubectl --context "${HUB_CTX}" get site production-nsw -o jsonpath='{.status.registrationURL}')"
kubectl --context "${NSW_CTX}" apply -f rendered/20-tun-device-plugin.yaml
kubectl --context "${NSW_CTX}" apply -f "${NSW_URL}"

QLD_URL="$(kubectl --context "${HUB_CTX}" get site production-qld -o jsonpath='{.status.registrationURL}')"
kubectl --context "${QLD_CTX}" apply -f rendered/20-tun-device-plugin.yaml
kubectl --context "${QLD_CTX}" apply -f "${QLD_URL}"

Verify Sites

kubectl --context "${HUB_CTX}" get siteregistration
kubectl --context "${HUB_CTX}" wait site/production-vic --for=jsonpath='{.status.phase}'=Connected --timeout=10m
kubectl --context "${HUB_CTX}" wait site/production-nsw --for=jsonpath='{.status.phase}'=Connected --timeout=10m
kubectl --context "${HUB_CTX}" wait site/production-qld --for=jsonpath='{.status.phase}'=Connected --timeout=10m

Create PostgreSQL

kubectl --context "${HUB_CTX}" create namespace database-platform
kubectl --context "${HUB_CTX}" apply -f docs/examples/multisite-postgres.yaml
kubectl --context "${HUB_CTX}" -n database-platform wait multisitepostgres/orders \
  --for=condition=Ready --timeout=30m

Caveats

  • Do not edit generated child resources on site clusters. Change the hub CRs.
  • Do not put passwords in manifests. Use Vault references only.
  • Use immutable image digests. Mutable tags are rejected for PostgreSQL runtime and upgrade images.
  • Registration URLs expire. Recreate or update the SiteRegistration if a bundle expires before apply.
