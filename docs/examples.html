Examples

These manifests are starting points. Replace site names, contexts, StorageClasses, issuers, Vault paths, domains, object storage, and PostgreSQL images.

ManifestApply toPurpose
site-registration.yamlHub clusterRegisters production-vic, production-nsw, and production-qld.
multisite-postgres.yamlHub clusterCreates the orders PostgreSQL instance across registered sites.
tenant.yamlHub clusterCreates one database declaration and one login role.
restore.yamlHub clusterRestores orders to a new orders-recovered instance.
upgrade.yamlHub clusterRuns a PostgreSQL 17 to 18 major upgrade using the released upgrade image.
released-images.envShellImage references for release automation.

Apply Order

  1. Install platform dependencies on every cluster.
  2. Apply CRDs, TUN plugin, and hub controller manifests to the hub cluster.
  3. Apply SiteRegistration resources to the hub cluster.
  4. Apply each generated registration bundle to the matching target cluster.
  5. Wait for every site to report Connected.
  6. Apply MultiSitePostgres to the hub cluster.
  7. Apply tenant, restore, or upgrade CRs only after the instance is ready.

Validate Before Apply

kubectl --context "${HUB_CTX}" apply --dry-run=server -f docs/examples/site-registration.yaml
kubectl --context "${HUB_CTX}" -n database-platform apply --dry-run=server -f docs/examples/multisite-postgres.yaml
kubectl --context "${HUB_CTX}" -n database-platform apply --dry-run=server -f docs/examples/tenant.yaml

Do not apply workload CRs to target clusters. Site clusters receive only registration bundles and generated local resources from their site agent.
