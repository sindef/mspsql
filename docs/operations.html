Backups

  • Backups require MultiSitePostgres.spec.backup.
  • Repository credentials are read from Vault at each site.
  • Use a unique repository prefix per instance.
  • Check status.lastBackupTime, status.recoveryWindowStart, and backup schedule status.

Restore

kubectl --context "${HUB_CTX}" -n database-platform apply -f docs/examples/restore.yaml
kubectl --context "${HUB_CTX}" -n database-platform get postgresrestore orders-pitr
kubectl --context "${HUB_CTX}" -n database-platform describe postgresrestore orders-pitr
  • Restore always creates a new target instance.
  • The source instance is not modified.
  • Expose applications only after the restored instance reports Ready.

Upgrade

kubectl --context "${HUB_CTX}" -n database-platform apply --dry-run=server -f docs/examples/upgrade.yaml
kubectl --context "${HUB_CTX}" -n database-platform apply -f docs/examples/upgrade.yaml
kubectl --context "${HUB_CTX}" -n database-platform describe postgresupgrade orders-pg18
  • Minor upgrades roll members and use Patroni switchover.
  • Major upgrades require backup, rollback storage policy, benchmark evidence, and a pinned upgrade image.
  • Rollback is automatic only while the write service has not been restored.
  • Do not start another restore or upgrade for the same instance.

Repair

  • For stuck operations, inspect status.operation, status.conditions, the owned directive ConfigMap, site-agent logs, and recent events in the affected site namespace.
  • A post-upgrade backup retries with bounded exponential backoff and jitter. If manualInterventionRequired is true, repair repository or credential access, collect the directive/job logs and events, then update the operation after confirming the required full backup can run.
  • For finalizers, prefer completing or rolling forward the recorded phase. Use force-abandon or force-orphan annotations only after recording residual PVCs, Secrets, ConfigMaps, Jobs, and site resources.

Deletion

  • Retain keeps PVCs, namespaces, and backups.
  • Delete permits namespace and PVC deletion after backup checks.
  • Disconnected sites can block finalization. Investigate before forcing orphaned resources.

Do Not

  • Do not edit generated StatefulSets, Services, Secrets, ConfigMaps, Jobs, or PVCs.
  • Do not put database passwords in CRs or Git.
  • Do not reuse backup prefixes or TDE key paths across independent instances.
  • Do not treat pod readiness as database readiness. Use CR conditions.
